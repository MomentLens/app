## 6. Cleanup

In a fresh session, once the stack is reviewed.

1. `git fetch --prune origin`, then list the slice's PRs: `gh pr list --state all --search "<id> in:title" --json number,title,state,headRefName,baseRefName,headRefOid,reviewDecision`.
2. **Check the readiness record before anything merges** (D-149). Take the head of the topmost open PR and run `node scripts/readiness.mjs --issue <n> --stage review --head <its headRefOid>`. It refuses while a ready-for-review row is missing, not met, or stale. A row is stale when it was recorded at a head whose changes differ from this one's; a fold that only replays the same commits keeps the same changes, so it passes and the check says so. When it refuses, stop and say which rows and what each waits on: evidence, a rerun of the done stage, or an exception only Ukasha can record in the issue. Never edit the record to make it pass.
3. **Fill the ready-to-merge rows** from what GitHub shows now, one section edit as SKILL.md says. Review: each PR's approval, or for a code owner's own stack its `/code-review ran` comment, which counts only when it names the head that PR has now or one holding the same changes. Human read: who read each human-read surface the PRs name, or `n/a: touches none`. A PR without either goes back to the done stage. Then run the check again with `--stage merge`.
4. **If any PR is still open**, the check passes, and every open one has green checks (`gh pr checks <n>`), list them top to bottom and offer to merge the stack. Merge only after the developer says yes, one PR at a time from the top: `gh pr merge <n> --rebase`, then `gh pr checks <next one down> --watch` until its checks pass, then the next. Folding the stack drops the bottom PR's approval: for anyone else's stack, stop there and ask the developer to get it approved again; for a code owner's, merge it with `gh pr merge <n> --rebase --admin`, which bypasses the review rule on `main` and never the CI rule. If GitHub cannot rebase one, stop and follow Handbook §12's conflict steps. If any open PR is not approved or not green, stop and say which, and what it waits on.
5. When the bottom PR has merged, check that the issue closed. If it is still open, close it with a comment listing the merged PRs.
6. **Post the evidence before deleting anything.** One issue comment holds the last `scripts/verify.mjs` table from `.slices/<id>/`, and the failing lines of any log the reviewer would need, since that folder is about to go.
7. **Check before deleting.** For each slice branch that exists locally, keep it and say why if its worktree has uncommitted changes (`git -C <path> status --porcelain`), or if `git cherry origin/main <branch>` prints a line starting with `+`: a commit whose change never reached `main`. Rebase and merge gives every commit a new id, so compare changes, never ids.
8. Remove every worktree on a slice branch you did not keep, with `git worktree remove <path>`, never `--force`, then `git worktree prune`. Keep a kept branch's worktree. Leave every worktree under `.claude/worktrees/`: the desktop app made it and removes it. If this session runs inside one of them, leave it and tell the developer to remove it from their main clone afterwards. List any other worktree whose branch shows `gone` in `git branch -vv`, and offer to remove it the same way.
9. Delete the local slice branches you did not keep with `git branch -D <branch>`. It has to be `-D`: Rebase and merge gives every commit a new id, so git cannot see that the branch merged. Step 7 is the check that replaces it.
10. **Bring `main` up to date** in the developer's main clone. If it is on a slice branch, `git switch main` first, unless Metro is serving it, in which case ask. Then `git pull --ff-only`. If `pnpm-lock.yaml` changed, run `pnpm install`. If `apps/mobile/package.json` or `apps/mobile/app.json` changed, tell the developer the development build may need a rebuild (Handbook §10).
11. **Put the dev server on `main`** if the stack touched `apps/api/`, `worker/` or `supabase/migrations/`, or its ledger says a slice branch was deployed. Offer `ssh momentlens 'sudo bash /srv/momentlens/scripts/deploy.sh --branch main'` (Handbook §13.4) and run it only on a yes.
12. Post this stage's ledger entry, then delete `.slices/<id>/`.
13. Report what was removed, what was kept and why, and what the developer still has to do.
