## 3. Schema

Load the card, as SKILL.md says, never the whole issue. If the card says the slice has no schema stage, stop and tell the developer the next stage is `/slice <id> build <first package in the card>`. `git fetch origin` and cut `feat/<id>-schema` from `origin/docs/<id>-rulings` if the read-back opened one, otherwise from `origin/main`. List what `packages/shared-types` exports, `grep -n '^export' packages/shared-types/src/*.ts`, and open only the files you will reuse or extend. Write the zod schemas the card's "Produces" line names, and nothing else: every request, response and error shape the slice's endpoints use, following the paths, error body and status codes in Handbook §5.3. Run `node scripts/verify.mjs packages --slice <id>`, which typechecks every package that imports the schemas.

Commit, push, and open the PR `<id>: schema` on the stack. Do not wait for a review or a merge. Show the developer each exported schema name with its fields in a short list, since every later stage builds on that contract, then post the ledger entry and tell them the next stage is `/slice <id> build <first package in the card>` in a fresh session.
